# 新增的欄位或分支沒交代誰用、何時會走到
- 重點：計畫或 diff 新增了從原始資料算出來的欄位、包裝層，或處理特殊情況的分支，卻沒有交代誰會讀它、什麼情況會走到。有四種：
  - 衍生欄位：把原始資料先轉成另一個欄位或分類，讀它的地方只有一處，那一處直接讀原始資料就能判斷。
  - 防禦分支：為某種輸入加了處理，卻沒有依據說這種輸入會出現。
  - 繞過去：某個做法失敗，沒查原因就換一個做法，為此多出欄位或狀態。
  - 吞掉錯誤：攔下例外後回空值或預設值，原本的錯誤內容沒有留給任何人看。
- 怎麼抓：
  - 衍生欄位：列出 diff 新增的欄位和包裝層，每一個在 diff 和計畫裡找讀它的地方。找不到讀者，或只有一處而且那一處拿得到原始資料，算用錯。ledger 定案裡使用者指定要這個欄位，不算用錯。
  - 防禦分支：列出 diff 新增的特殊情況分支，每一個找依據：型別定義、文件、實際遇過的紀錄。找不到依據，算用錯。依據有附但手上的資料看不出對不對，標 ask。
  - 繞過去：diff 或計畫的說明寫到某個做法失敗而改用另一個時，看有沒有寫失敗的原因。沒寫原因，算用錯。
  - 吞掉錯誤：列出 diff 新增的例外攔截，看攔下後錯誤內容有沒有往外傳（顯示、記錄、回傳）。沒有，算用錯。
  - 只看得到新增的那一段、看不到讀它的程式時，標 ask。
- 例子：
  - 衍生欄位：一個送出請求的函數，回傳原始回應之外，還加了一個把回應分成四類的欄位。這個欄位只有顯示訊息的地方讀，而那裡本來就拿得到原始回應。
  - 防禦分支：同一個函數為「回應不是預期的形狀」加了兩條分支。外部介面的型別定義上這兩種情況不會出現，也沒有實際遇過。
  - 繞過去：畫面上一個值清不掉，agent 沒查原因，另外加兩個狀態欄位記錄它是否過期。
  - 吞掉錯誤：取清單的函數攔下所有例外後回空清單，畫面只顯示取不到，真正的原因看不到。
