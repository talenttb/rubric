# 新增的東西沒交代既有的為什麼不能用
- 重點：計畫或 diff 新增了檔案、模組、namespace、函數或畫面區塊，卻沒有交代既有同用途的為什麼不能用。
- 怎麼抓：
  - 列出計畫或 diff 新增的每個檔案、模組、namespace、函數、畫面區塊（新的版面結構、樣式類別）。
  - 每一個找交代：計畫、diff 的說明或 ledger 定案裡，有沒有寫既有的哪一個最接近、為什麼不能用。
  - 找不到交代，算用錯。
  - 交代沒有指出既有的哪一個，只寫「職責不同」「比較清楚」這類理由，算用錯。
  - 交代寫的是既有的缺某個能力，卻沒有 ledger 定案記錄使用者同意另做一個，算用錯。
  - ledger 定案裡使用者指定要新增這一個，不算用錯。
  - 有交代，但手上的資料看不出既有的是不是真的不能用，標 ask。
  - 新增的是畫面區塊，而 diff 看不到同一頁既有區塊的寫法，標 ask。
- 例子：
  - 檔案：計畫要為一個新功能開三個新檔，計算、查詢、排程各一個，沒有說明各自為什麼不能放既有的檔。使用者問了之後才發現，計算和查詢放進同領域既有的兩個檔就夠了，只有排程因為相依方向的限制必須另開。
  - 函數：某種通知已有一個共用的顯示函數。diff 為新功能另加一個只給它用的顯示函數，沒有說明共用的缺什麼。使用者看到後才知道，agent 是因為共用的少一種狀態，就繞過它另寫。
  - 畫面區塊：頁面上已有兩個同形式、可收合的區塊。diff 把新功能做成另一種版面，放在主要內容旁邊，擠掉主要內容的寬度。使用者指出應該沿用頁面現成的形式。
