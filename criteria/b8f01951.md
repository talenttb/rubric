# 說法沒查證就拿來用
- 重點：提案、計畫或提問裡，把一個說法當成事實來用，卻沒有對過程式碼、實際行為或原始資料。說法的來源有兩種：
  - 資料裡寫的：計畫檔、交接單、筆記列為問題或事實的項目。
  - agent 自己講的：設計理由、對現況的描述。
- 怎麼抓：
  - 列出提案或計畫所依據的事實說法：哪些項目被列為問題、每個設計決定的理由是什麼。
  - 每個說法看有沒有查證來源：檔案位置、指令輸出、實測結果。沒有就算用錯。
  - 標了「還沒查」「推測」的說法，看它有沒有被當成已確定的前提往下用；有就算用錯。
  - 資料列為問題的項目，看 agent 有沒有先確認它從正常操作碰得到；沒確認就拿去問使用者要不要修，算用錯。
  - 來源有附，但手上的資料看不出查得對不對，標 ask。
- 例子：
  - 資料裡寫的：計畫檔列出某功能在某個設定下沒有資料。接手的 agent 沒查這個設定在介面上選不選得到，就問使用者這輪要不要補。使用者指出那是正常行為。
  - agent 自己講的：agent 提議加一層過濾，理由是某個欄位有時會被送回後端。這個欄位其實不會送回，agent 被問到才去查。過濾仍然需要，但理由換了。
