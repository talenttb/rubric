# 使用者的話和依據的資料沒互相對過
- 重點：agent 提案、實作或回答時依據了某份資料，卻沒有把它和使用者的原話、已定案的決定互相對過。依據的資料包括：交接單、前一個 agent 的筆記或摘要、規格文件、ledger 裡不是使用者原話的部分、程式碼的實際行為。有三種：
  - 多的：資料裡寫的「需要 X」直接當成使用者的需求。
  - 缺的：資料裡斷掉、寫一半，或標成未解、待確認的項目，沒處理就略過。
  - 對不上的：使用者的預期和資料顯示的不同，agent 沒指出落差，只回答了別的問題，或照其中一邊做。
- 怎麼抓：
  - 多的：
    - 找 agent 提案或實作所依據的需求，看它出自哪裡。
    - 出自上面那些資料時，查 agent 動手或提案前，有沒有去對使用者原話或定案紀錄。
    - 沒對就算用錯；有對但對不到、仍當需求處理，也算用錯。
  - 缺的：
    - 讀 agent 依據的資料，列出斷句和標成未解、待確認的項目。
    - 看 agent 的提案或項目清單有沒有涵蓋每一項，或明講不做。
    - 沒涵蓋，也沒有翻原始紀錄或問使用者，就算用錯。
  - 對不上的：
    - 找使用者對功能或行為的預期：提問、說功能沒作用、描述他以為會怎樣。
    - 看 agent 當時已經讀到的資料顯示的行為是什麼。
    - 兩邊不同，而 agent 的回覆沒有明講「預期是 A，實際是 B」，就算用錯。
    - 使用者沒講清楚預期，agent 沒問就下結論，也算用錯。
  - 對話裡看不出需求來源或使用者的預期，或看不到資料、定案紀錄的內容時，標 ask。
- 例子：
  - 多的：交接單列出某功能需要三種狀態，其中一種是前一個 agent 自己加的。接手的 agent 沒查來源，就要使用者選這個狀態要怎麼實作。
  - 缺的：交接單的未解項目裡有一句寫到一半的話。接手的 agent 沒有補齊這句，照其他項目做完並回報完成，使用者才指出那一項是重點。
  - 對不上的：使用者說某一頁的即時更新沒作用。agent 查出連線和資料流正常，回答沒壞，沒提到這一頁的即時更新本來就只顯示事件、不顯示現況。使用者再問一輪，才知道他預期的功能在另一頁。
