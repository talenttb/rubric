# 二手文件沒對回使用者決定就定範圍
- 重點：agent 依據交接單、前一個 agent 的筆記或摘要來提案或實作，沒有對到使用者原話或已定案的紀錄就定了範圍。有兩種：
  - 多的：文件裡寫的「需要 X」直接當成使用者的需求。
  - 缺的：文件裡斷掉、寫一半，或標成未解、待確認的項目，沒處理就略過。
- 怎麼抓：
  - 多的：
    - 找 agent 提案或實作所依據的需求，看它出自哪裡。
    - 出自二手文件時，查 agent 動手或提案前，有沒有去對使用者原話或定案紀錄。
    - 沒對就算用錯；有對但對不到、仍當需求處理，也算用錯。
  - 缺的：
    - 讀 agent 依據的二手文件，列出斷句和標成未解、待確認的項目。
    - 看 agent 的提案或項目清單有沒有涵蓋每一項，或明講不做。
    - 沒涵蓋，也沒有翻原始紀錄或問使用者，就算用錯。
  - 對話裡看不出需求來源，或看不到二手文件、定案紀錄的內容時，標 ask。
- 例子：
  - 多的：交接單列出某功能需要三種狀態，其中一種是前一個 agent 自己加的。接手的 agent 沒查來源，就要使用者選這個狀態要怎麼實作。
  - 缺的：交接單的未解項目裡有一句寫到一半的話。接手的 agent 沒有補齊這句，照其他項目做完並回報完成，使用者才指出那一項是重點。
