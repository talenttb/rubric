# 二手需求沒對到使用者決定就當需求
- 重點：agent 把交接單、前一個 agent 的筆記或摘要裡寫的「需要 X」直接當成使用者的需求，據此提案或實作，沒有先對到使用者原話或已定案的紀錄。
- 怎麼抓：
  - 找 agent 提案或實作所依據的需求，看它出自哪裡。
  - 出自二手文件時，查 agent 動手或提案前，有沒有去對使用者原話或定案紀錄。
  - 沒對就算用錯；有對但對不到、仍當需求處理，也算用錯。
  - 對話裡看不出需求來源、或看不到定案紀錄內容時，標 ask。
- 例子：交接單列出某功能需要三種狀態，其中一種是前一個 agent 自己加的。接手的 agent 沒查來源，就要使用者選這個狀態要怎麼實作。
