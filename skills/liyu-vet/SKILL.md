參數：$ARGUMENTS

路徑：`RUBRIC=~/talenttb/rubric`。
- 信：`$RUBRIC/inbox/*.md`
- scan 判準：`$RUBRIC/scan-criteria.md`
- 審核規則：`$RUBRIC/criteria/INDEX.md`（索引）＋ `$RUBRIC/criteria/<短 uuid>.md`（一條一檔）

不得掃 home 根層或 ~/Library。

## --help
有 `--help` 就只印這段，然後結束：
```
/liyu-vet         從最舊的信開始，一封一封處理
/liyu-vet --help  顯示這段

每封信最後選：
  r  更新審核規則
  s  更新 scan 判準（這類對話下次不拉，或漏抓的這類要拉）
  x  刪除信件，換下一封
  p  跳過，信留著，換下一封
```

## 開始
1. `scan-criteria.md` 或 `criteria/` 有沒 commit 的改動（上次中途停下），先 commit。git 一律用 `git -C ~/talenttb/rubric`，不管目前在哪個專案。
2. 讀 `scan-criteria.md` 和 `criteria/INDEX.md`。
3. 告訴使用者有幾封，從最舊的開始。

## 每一封
1. 讀完整封信。使用者不看 inbox，由你告訴他這封要處理什麼。
   - 「前文」「後文」是腳本貼的相鄰回合，只當背景，不拿來當 r／s 的依據。
   - 信裡缺的回合：先看 frontmatter 的 `prev`／`next`（同 session 相鄰的信）；舊信沒有這兩欄，或要找的回合不在相鄰的信時，拿信裡提到的回合 uuid 前 8 碼 grep `inbox/`。在另一封信裡，就把那封一起讀，合併成一次開場，每封各給一個建議；使用者各回一個字母，處理完一起刪。
2. 寫開場前先對照三樣，結果只在開場對應的那一段寫出來，沒對上的不寫：
   - 現行 scan 判準：信裡每一段對照 `scan-criteria.md` 的「不拉」。符合的那一段不拿來當 r 的依據。inbox 的信可能是舊版判準拉的。
   - 現行 CLAUDE.md：全域 `~/.claude/CLAUDE.md` 和信裡 `project` 那個專案根目錄的 `CLAUDE.md`（沒有這個檔就略過）。
   - 既有審核規則。
3. 開場照這個順序寫，目標是使用者看完前幾行就能回 r／s／x／p，整段約 20 行：
   1. 標題一行：第 N 封，共 M 封｜專案｜階段。
   2. 建議：明講建議選 r／s／x／p 哪一個，只選一個，附一句理由。
   3. 發生了什麼：2–3 句白話，沒看過對話也懂。
   4. 會改變決定的點：最多 3 點，每點標「信裡寫的」或「我推論」。信裡缺的背景、符合 scan「不拉」的段落，會影響決定才寫；缺的直說缺，不要補。
   5. 已經有管到的：一條一行，寫問題和出自哪一份 CLAUDE.md 的哪一段、或哪一條審核規則，不引原文。
   6. 反方：一句。
   7. 要使用者自己決定的事（例如外洩的密碼要不要換）：有才寫，有就一定要講。
   使用者要看細節（原文、其他注意到的事）時再展開。
4. 開場最後一定附這一行：`回 r 改審核規則｜s 改 scan 判準｜x 刪信｜p 跳過`
   使用者可以先討論，討論完再選。
5. 當場操作類問題（例如動憑證、印出機密）不算審核規則，不要提議 r。
6. 選 r：把相關的既有規則都列出來，和使用者一起討論要新增、修改或刪除哪幾條；一封信可以改好幾條。不要自己判定哪條不適用。
7. 選 r 或 s：先給使用者看改動全文，一起調整，同意才寫；寫完用 `git -C ~/talenttb/rubric` commit（只 commit `scan-criteria.md`、`criteria/`），再刪信。
8. 使用者說 scan 漏抓了某類對話：用 s 在 `scan-criteria.md` 加「這類要拉」。
9. 使用者想自己加一條規則（不是從信來的）：照 r 的方式討論、寫入。使用者也可以直接改 `criteria/` 的檔。

## 審核規則的寫法
`criteria/INDEX.md` 不分大類，每條規則一行，標題後面貼標籤：
```
- [<標題>](<短 uuid>.md) `<標籤>` `<標籤>`：什麼情境適用
```
INDEX 那一行只寫適用情境，讓 audit 判斷要不要打開這條；要抓什麼、例子都寫在規則檔。
`criteria/<短 uuid>.md`，照重要程度排，例子放最後：
```
# <標題>
- 重點：要抓的「用錯」是什麼。
- 怎麼抓：用什麼資料、怎麼判斷；判斷不了的標 ask。
- 例子：泛用的情境描述。
```
- 短 uuid：`uuidgen | cut -c1-8 | tr A-F a-f`，不用流水號。
- 標籤：英文小寫，多個字用 `-` 連接，一條規則可以貼好幾個。寫這條規則特有的情境、對象或用錯的種類，讓人找得到這條、不漏掉。每條規則都貼得上的標籤不用。貼之前先看既有標籤，意思相同就沿用；貼什麼和使用者討論。
- 寫成泛用的，不針對單一情境；不放原話、姓名、帳號或任何號碼；不寫來源、不寫範圍。
- 和 CLAUDE.md 衝突時要指出來。

## 結束
使用者喊停或 inbox 清空時，回報處理了幾封、剩幾封、改了哪些規則。
